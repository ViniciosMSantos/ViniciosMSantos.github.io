Projeto pessoal

Dashboard de operações da Olist

Google Apps Script JavaScript Databricks Chart.js
Ver dashboard ao vivo ↗ Ver no GitHub ↗

Contexto

Dashboard de operações da Olist (marketplace de e-commerce brasileiro), consultando dados diretamente do Databricks. Cobre visão geral do negócio, vendas, logística/entrega e satisfação dos clientes — 5 páginas no total: Visão Geral, Receita & Performance, Vendas, Logística e Satisfação.

Cada página é guiada por uma sequência de perguntas de negócio (ex.: "Como está o negócio?", "Onde está o gargalo do processo?") e responde com KPIs + gráficos, sempre comparando o mês selecionado com o mês anterior.

Arquitetura

Google Apps Script HTML Service (frontend) → Code.gs (backend) → Databricks Statement Execution API

O frontend é uma SPA simples servida via Apps Script (index.html, Stylesheet.html, JavaScript.html), com navegação por seções e gráficos em Chart.js 4. O backend (Code.gs, Apps Script/V8) consulta as tabelas gold do Databricks via Statement Execution API, com cache via CacheService. Deploy feito com clasp, acesso restrito ao próprio autor.

Tecnologias

Google Apps Script · JavaScript · Chart.js 4 · Databricks SQL (tabelas gold) · Google Fonts (Inter)

Limitações dos dados

As tabelas gold cobrem set/2016 a ago/2018, com volume real a partir de jan/2017 — por isso o dashboard só mostra os 2 meses mais recentes com pelo menos 100 pedidos. O que os dados não têm, para não inventar ao interpretar um número:

  • Custo do produto (COGS) — não existe margem de lucro real, só a composição faturamento/frete
  • Custo real de logística — "custo de frete" é o que o cliente pagou, não o custo da Olist
  • Nome de produto (só categoria) e nome de cliente/vendedor (só ids)
  • Causalidade — os dados mostram associação (ex.: atraso × nota), não causa
