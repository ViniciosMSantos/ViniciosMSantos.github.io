Projeto pessoal

pipeline_dados_v2 — Pipeline de dados do e-commerce Olist

Python Airflow dbt Databricks Docker Power BI
Ver no GitHub ↗

Contexto

Projeto pessoal para praticar engenharia de dados de ponta a ponta fora do ambiente de trabalho: construir um pipeline completo de e-commerce a partir do dataset público Olist, cobrindo orquestração, transformação, testes, containerização e consumo analítico.

Arquitetura

Airflow (orquestração) → dbt (transformação/testes) → Databricks (Bronze → Silver → Gold) → Power BI (consumo)

O princípio central: o Airflow não contém lógica SQL — ele só aciona o dbt, que cuida de SQL, dependências entre modelos, testes, documentação e materializações. Isso permite reprocessar um domínio isoladamente (ex.: orders) sem rodar o pipeline inteiro de novo.

Tudo roda containerizado (dbt e Airflow em imagens Docker próprias, orquestradas via Docker Compose com Postgres para o metastore do Airflow), com CI no GitHub Actions e deploy automático via runner self-hosted a cada push na master.

Tecnologias

Python · SQL · Airflow 3 · dbt · Databricks · Docker & Docker Compose · GitHub Actions · Power BI

Estado atual

  • Projeto dbt inicializado, com as sources da camada Bronze declaradas
  • Primeiro modelo Silver implementado (slv_clientes), com testes not_null
  • Imagem Docker do dbt containerizada e validada contra o Databricks
  • Stack de orquestração no ar: Airflow 3 (api-server + scheduler + dag-processor + Postgres) via Docker Compose, com o primeiro DAG rodando o container dbt de ponta a ponta
  • CI básico no GitHub Actions, buildando a imagem dbt

Pendente: os demais modelos Silver, a camada Gold, mais testes e DAGs, retries/alertas, separação formal entre ambientes de desenvolvimento e produção, e um CI/CD que rode de fato dbt build/test.

📝 Projeto pessoal de prática, em desenvolvimento ativo — não é um sistema em produção com usuários reais. O foco é demonstrar domínio da arquitetura e das ferramentas de engenharia de dados.
